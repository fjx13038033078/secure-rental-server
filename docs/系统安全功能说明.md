# 汽车租赁系统安全功能说明文档

本文档描述系统已实现的安全功能，包括用户身份验证与会话安全、数据安全存储与隐私防护、系统级安全与防灾、以及汽车租赁业务流转等模块。所有内容均基于当前代码实现，并标注对应代码位置。

---

## 一、用户身份验证与会话安全模块

### 1.1 密码加盐哈希存储

**实现逻辑：** 采用 Bcrypt 算法对用户密码进行单向加密，数据库仅存储哈希值，绝不存储明文密码。Bcrypt 自带盐值（Salt），每次加密同一密码也会产生不同哈希，有效抵御彩虹表攻击。

**代码位置：**

| 功能       | 文件路径                                                                 | 说明                                   |
|------------|--------------------------------------------------------------------------|----------------------------------------|
| 登录校验   | `org.dromara.web.service.impl.PasswordAuthStrategy`             | `BCrypt.checkpw(password, user.getPassword())` 校验密码 |
| 用户新增   | `org.dromara.system.controller.system.SysUserController`       | `BCrypt.hashpw(user.getPassword())` 入库前加密   |
| 密码重置   | `org.dromara.system.controller.system.SysUserController`       | 同上                                   |
| 修改密码   | `org.dromara.system.controller.system.SysProfileController`    | 校验旧密码后 `BCrypt.hashpw` 新密码     |
| 用户注册   | `org.dromara.web.service.SysRegisterService`                    | `BCrypt.hashpw(password)` 注册时加密   |
| 用户导入   | `org.dromara.system.listener.SysUserImportListener`            | 导入时对初始密码加密                   |

### 1.2 防暴击验证码

**实现逻辑：** 登录与注册时启用图形验证码，验证码答案存入 Redis，以 UUID 为 key。用户提交时从 Redis 取出并比对，校验后立即删除，防止重复使用。验证码过期由 Redis TTL 控制，有效防止机器人脚本批量撞库。

**代码位置：**

| 功能       | 文件路径                                                       | 说明                                           |
|------------|----------------------------------------------------------------|------------------------------------------------|
| 验证码校验 | `org.dromara.web.service.SysRegisterService`                    | `validateCaptcha()` 中 `RedisUtils.getCacheObject(verifyKey)` 取验证码，`RedisUtils.deleteObject` 删除 |
| 配置       | `application.yml`                                              | `captcha.enable: true`，`captcha.type: math`   |
| 验证码生成 | `org.dromara.common.web.config.CaptchaConfig`                  | 图形验证码配置与生成逻辑                       |

### 1.3 JWT 令牌无状态认证

**实现逻辑：** 采用 Sa-Token 签发 JWT Token，前端在请求头中携带 `Authorization` 访问接口。Token 包含用户身份信息，服务端无需在内存中维护会话，实现无状态认证。

**代码位置：**

| 功能       | 文件路径                                           | 说明                          |
|------------|----------------------------------------------------|-------------------------------|
| Token 配置 | `application.yml`                                 | `sa-token.token-name: Authorization`，`jwt-secret-key` |
| 依赖       | `pom.xml`                                         | `sa-token-spring-boot3-starter`，`sa-token-jwt` |

### 1.4 会话生命周期控制

**实现逻辑：** Sa-Token 与 Redis 集成，Token 及会话信息存储在 Redis 中。支持用户主动登出（作废 Token），以及超时自动过期（Redis TTL 剔除）。配置项控制是否允许同一账号并发登录、是否共用 Token。

**代码位置：**

| 功能       | 文件路径                                         | 说明                                      |
|------------|--------------------------------------------------|-------------------------------------------|
| 会话配置   | `application.yml`                               | `sa-token.is-concurrent`、`sa-token.is-share` |
| Redis 集成 | 各环境 `application-*.yml`                      | Redis 连接配置，Token 存储于 Redis        |

### 1.5 离线 IP 城市解析

**实现逻辑：** 采用 Ip2region 离线库，根据登录 IP 解析归属地（国家、省份、城市等）。登录日志记录时调用 `AddressUtils.getRealAddressByIP(ip)`，内部使用 `RegionUtils.getRegion(ip)` 进行毫秒级查询，无需依赖外部 API。

**代码位置：**

| 功能       | 文件路径                                                       | 说明                                           |
|------------|----------------------------------------------------------------|------------------------------------------------|
| IP 解析    | `org.dromara.common.core.utils.ip.RegionUtils`   | `getRegion(ip)` 使用 Ip2region 查询城市        |
| 地址封装   | `org.dromara.common.core.utils.ip.AddressUtils` | `getRealAddressByIP(ip)` 内网判断后调用 RegionUtils |
| 登录记录   | `org.dromara.system.service.impl.SysLogininforServiceImpl` | `address = AddressUtils.getRealAddressByIP(ip)` 写入 `login_location` |
| 依赖       | `pom.xml`                                                      | `ip2region` 依赖                              |

## 二、数据安全存储与隐私防护模块

### 2.1 敏感数据透明加密（AES-256-GCM）

**实现逻辑：** 针对客户表中的 `phone`、`id_card` 字段，在 MyBatis 层编写自定义 TypeHandler。业务代码读写明文，数据在持久化到 MySQL 前自动 AES-256-GCM 加密，查询时自动解密。存储格式为 Base64(IV + 密文+认证标签)，每次加密使用随机 12 字节 IV，保证同一明文多次加密结果不同；GCM 模式提供认证标签，防止密文被篡改。

**代码位置：**

| 功能       | 文件路径                                                                 | 说明                                                                 |
|------------|--------------------------------------------------------------------------|----------------------------------------------------------------------|
| TypeHandler| `org.dromara.rental.handler.AesGcmTypeHandler`         | `setNonNullParameter` 入库加密，`getNullableResult` 出库解密         |
| 实体绑定   | `org.dromara.rental.domain.BusCustomer`                | `@TableField(typeHandler = AesGcmTypeHandler.class)` 绑定 phone、idCard |
| 密钥配置   | `org.dromara.rental.config.AesKeyConfig`              | `@Value` 注入密钥，`@PostConstruct` 解码为 32 字节   |
| 配置示例   | `application-dev.yml`                                 | AES 密钥配置项，Base64 编码的 32 字节密钥                       |

### 2.2 轻量级密钥管理

**实现逻辑：** 密钥通过 `application.yml` 中的配置项注入，避免硬编码。AesKeyConfig 在 Spring 启动时加载密钥到静态变量，供 TypeHandler 使用。TypeHandler 由 MyBatis 实例化，无法直接使用 `@Value`，故采用配置类桥接，模拟 KMS 的物理隔离思路。

**代码位置：** 同上 `AesKeyConfig.java`、`application-*.yml`。

### 2.3 多维数据脱敏技术

**实现逻辑：** 客户手机号、身份证号在返回前端前进行脱敏。Service 层在 `queryById`、`queryPageList`、`queryList` 返回前调用 `applyMask()`，对 `phone`、`idCard` 进行解密（若为加密串）并脱敏：手机号前 3 后 2（如 `130******78`），身份证前 6 后 4（如 `110101********1234`）。当 TypeHandler 未生效导致返回加密串时，`CustomerMaskUtils` 会先解密再脱敏，保证前端始终展示脱敏数据。

**代码位置：**

| 功能       | 文件路径                                                                 | 说明                                                       |
|------------|--------------------------------------------------------------------------|------------------------------------------------------------|
| 脱敏工具   | `org.dromara.rental.utils.CustomerMaskUtils`           | `maskPhone()`、`maskIdCard()`，`isLikelyEncrypted()` 判断密文 |
| Service 应用| `org.dromara.rental.service.impl.BusCustomerServiceImpl`        | `applyMask(vo)` 在返回前对 phone、idCard 脱敏              |
| 静态解密   | `org.dromara.rental.handler.AesGcmTypeHandler`         | `decryptValue()` 供 Service 层解密加密串                   |

### 2.4 前端防傻设计

**实现逻辑：** 客户管理页面在修改时，若用户未修改手机号、身份证号（输入框仍为脱敏值，含 `*`），则禁止提交，并提示“请重新输入完整信息”，防止将脱敏数据误写回数据库。

**代码位置：** `secure-rental-ui/src/views/rental/customer/index.vue`，`validateNoMaskedData()`、表单校验 `validator` 中检测 `*`。

## 三、系统级安全与防灾模块

### 3.1 应用层细粒度访问控制（RBAC）

**实现逻辑：** 采用 Sa-Token 的 `@SaCheckPermission` 注解，在接口层按权限标识（如 `rental:customer:list`、`rental:car:add`）严格限制访问。不同角色在菜单管理中配置不同权限，实现细粒度控制，无需为底层 MySQL 账号分配复杂权限。

**代码位置：**

| 模块       | 文件路径                                                                 | 权限示例                                           |
|------------|--------------------------------------------------------------------------|----------------------------------------------------|
| 客户管理   | `org.dromara.rental.controller.BusCustomerController` | `rental:customer:list`、`add`、`edit`、`remove`、`export` |
| 车辆管理   | `org.dromara.rental.controller.BusCarController`       | `rental:car:list`、`add`、`edit`、`remove`、`export` |
| 租赁订单   | `org.dromara.rental.controller.BusRentalOrderController` | `rental:order:list`、`add`、`edit`、`remove`、`export` |

### 3.2 操作审计与防注入

**实现逻辑：** 使用 `@Log` 注解记录操作日志，记录操作人、时间、IP、接口、业务类型及核心数据变更。日志写入 `sys_oper_log` 表，支持按时间、业务类型等查询。SQL 层面全面使用 MyBatis-Plus 的 `LambdaQueryWrapper` 与预编译 SQL（`#{}`），从根源上防止 SQL 注入。

**代码位置：**

| 功能       | 文件路径                                                                 | 说明                                                       |
|------------|--------------------------------------------------------------------------|------------------------------------------------------------|
| 审计注解   | `org.dromara.rental.controller.BusCustomerController` 等 | `@Log(title = "客户管理", businessType = BusinessType.INSERT)` 等 |
| 条件构造   | `org.dromara.rental.service.impl.BusCustomerServiceImpl` | `LambdaQueryWrapper`、`Wrappers.lambdaQuery()` 构建查询   |

## 四、业务载体：汽车租赁业务流转模块

### 4.1 客户信息管理

**实现逻辑：** 客户表 `bus_customer` 存储客户姓名、手机号、身份证号、账号状态等。手机号、身份证号通过 AesGcmTypeHandler 透明加密存储，返回时经 `CustomerMaskUtils` 脱敏展示。支持按姓名、账号状态查询，CRUD 完整。

**代码位置：**

| 功能       | 文件路径                                                                 | 说明                           |
|------------|--------------------------------------------------------------------------|--------------------------------|
| Controller | `org.dromara.rental.controller.BusCustomerController` | `/rental/customer` 增删改查   |
| Service    | `org.dromara.rental.service.impl.BusCustomerServiceImpl`       | 查询、脱敏、CRUD 逻辑          |
| 前端页面   | `secure-rental-ui/src/views/rental/customer/index.vue`                  | 客户管理列表、表单、防傻校验   |

### 4.2 车辆图文管理（结合 OSS）

**实现逻辑：** 车辆表 `bus_car` 存储车牌、品牌车型、日租金、车辆状态等。车辆主图 `car_image_url` 使用系统内置 OSS 功能，前端通过 `ImageUpload` 组件上传至 MinIO，返回 URL 存入数据库。列表与表单中使用 `ImagePreview` 展示图片。

**代码位置：**

| 功能       | 文件路径                                                                 | 说明                                   |
|------------|--------------------------------------------------------------------------|----------------------------------------|
| Controller | `org.dromara.rental.controller.BusCarController`       | `/rental/car` 增删改查、导出           |
| 实体       | `org.dromara.rental.domain.BusCar`                     | `carImageUrl` 存储 OSS 链接             |
| 前端页面   | `secure-rental-ui/src/views/rental/car/index.vue`                       | `ImageUpload`、`ImagePreview` 组件     |

### 4.3 租赁订单状态机（事务一致性）

**实现逻辑：** 租车时校验车辆状态为待租（0），按起止日期与日租金计算总金额，生成订单号并插入订单，同时将车辆状态更新为已租出（1）。还车时更新订单状态为已还车（1），同时将车辆状态恢复为待租（0）。租车、还车均使用 `@Transactional` 保证多表更新的事务一致性。

**代码位置：**

| 功能       | 文件路径                                                                 | 说明                                                       |
|------------|--------------------------------------------------------------------------|------------------------------------------------------------|
| 租车       | `org.dromara.rental.service.impl.BusRentalOrderServiceImpl`    | `createOrder()`：校验车辆、计算金额、插入订单、更新车辆状态 |
| 还车       | 同上                                                                     | `returnCar()`：更新订单状态、恢复车辆状态                   |
| Controller | `org.dromara.rental.controller.BusRentalOrderController` | `POST /rental/order/create`、`PUT /rental/order/return/{orderId}` |
| 前端页面   | `secure-rental-ui/src/views/rental/order/index.vue`                     | 新建租车单、还车按钮、客户/车辆下拉选择                     |

## 五、技术栈与配置摘要

| 类别       | 技术/组件        | 用途                         |
|------------|------------------|------------------------------|
| 认证授权   | Sa-Token + JWT   | 无状态 Token、权限校验       |
| 密码存储   | Bcrypt           | 密码单向哈希                 |
| 验证码     | Redis + 图形验证码 | 防暴击、防撞库               |
| 会话存储   | Redis            | Token、验证码、会话          |
| IP 解析    | Ip2region        | 离线 IP 归属地查询           |
| 敏感加密   | AES-256-GCM      | 客户手机号、身份证号透明加密 |
| 数据脱敏   | CustomerMaskUtils | 手机前3后2、身份证前6后4     |
| 对象存储   | MinIO            | 车辆主图                     |
| 数据访问   | MyBatis-Plus     | 预编译 SQL、Lambda 条件构造  |
